# Whistle.mock-plugins

一个强大的 Whistle 插件，用于快速创建 API 模拟数据，提供友好的用户界面和丰富的功能。

## 项目概述

这是一个 Whistle 的插件，主要用于功能级别的接口代理和 response 的 mock 功能，配备美观的用户界面。插件提供了丰富的接口模拟功能，可以帮助前端开发人员在后端 API 尚未开发完成的情况下继续工作。

## 使用方法

1. 安装 Whistle：`npm install -g whistle`
2. 安装插件：`npm install -g whistle.mock-plugins`
3. 启动 Whistle：`w2 start`
4. 访问插件页面：`http://local.whistlejs.com/plugin.mock-plugin/`
5. 创建功能模块和接口配置
6. 在 Whistle 中添加规则：`pattern whistle.mock-plugins://`

### UI 3.0 工作区

接口页采用模块 / 分组、接口列表、详情编辑三栏布局，可拖动或用键盘调整分隔栏。窄屏下在列表与详情之间切换；布局、密度及主题保存在浏览器。批量表格支持选择显示列。编辑的响应与默认响应分别管理，修改保存后生效，离开未保存草稿会提示。

嗅探页支持发送真实请求、查看完整响应、保存为 Mock 或追加到已有接口；旧版本的历史摘要需重新发送后保存。统计页使用同一日期和 URL 条件展示概览、趋势和最近请求。

开发验证可在 `whistle.mock-plugin` 目录运行 `node scripts/preview-ui.js`，访问 [隔离预览](http://127.0.0.1:9083)。该预览使用临时示例数据。实施与验收状态见 [UI 3.0 待办](docs/ui-3.0-todo.md)。

在设置的外观区域可切换 **UI 3.0 工作台 / 经典 UI 2.0**，两个界面读取同一套正式数据（`~/.whistle-mock-plugin/data`）。9083 端口是示例数据预览；查看原有数据请打开 Whistle 的 Mock 插件页面。

### Whistle 抓包列表（1.4.0-beta.4）

UI 3.0 顶部和 UI 2.0 侧栏的“抓包列表”共用同一页面，可查看 Whistle 当前缓存的请求，支持 URL、方法和状态筛选、暂停/继续、请求与响应详情，并将完整 HTTP 文本响应创建为 Mock 或追加到已有接口。仅在 Whistle 插件页面运行时读取同源 Network API，沿用浏览器登录态；无需额外配置 token。页面首次取最近 50 条，随后增量同步，最多保留 500 条摘要；清空本页不删除 Whistle 的抓包。记录不会写入插件日志或浏览器本地存储。Whistle 已淘汰、未捕获、截断、二进制或超过 5 MB 的正文不能作为完整文本 Mock 导入；WebSocket 帧仍在 Whistle 中查看。从抓包创建的 Mock 默认停用，可在保存时选择启用。

### 故障复现会话（开发中）

在 UI 3.0 顶部或 UI 2.0 侧栏打开「故障复现」，在左侧选择手机 IP。可以留空入口地址，看到「抓取中」后让对方重新打开页面并操作到问题出现，再结束抓取。留空时会录制所选设备在这段时间的请求，并从完整 HTML 响应中识别入口，也可以手动切换。URL 的 `#` 路由不会发给代理，可在复现中从入口操作，或补填客户复制的完整 URL。填写入口地址时，会按入口域名、Referer、Origin 和已关联资源识别请求，也可以手动补充域名。左侧可按 URL、请求方法和状态搜索或筛选，点击请求可查看查询参数、请求头和响应头、格式化正文，也可保存或重新打开会话 JSON。

在 Whistle 所在电脑通过 localhost 或 127.0.0.1 打开插件。结束抓取或打开会话文件后，在右侧点「在 Chrome 窗口复现」即可在独立窗口操作，插件页面会显示回放状态和未匹配请求。需要安装 Chrome，并使用 Node.js 20 或更新版本运行 Whistle。也可以通过 `MOCKMASTER_REPLAY_NODE` 指定本机的新版 Node.js 路径。

可在「缺失资源直连」中多选类型。已打开 Chrome 窗口时，调整类型后点「应用并重新加载」即可更新当前回放。已录制的资源照常回放，未录到的对应资源会绕过 Whistle，从公网域名获取。直连成功按类型计数，失败会显示在诊断中。

回放在隔离 Chrome 中模拟手机视口。它优先按方法、完整 URL 和请求体匹配记录，依照捕获顺序返回状态码、正文和延迟。匹配时会兼容已识别的动态追踪 ID 和 JSONP 回调名，其余业务参数仍须一致。缺失的请求会被拦截并显示在插件面板中。如果同一接口只因参数不同而未匹配，可逐条选择抓取响应并应用例外。例外按请求方法、域名、路径和类型生效，仅保留在本次 Chrome 窗口中，可随时撤销。点击「重新加载入口」会从头使用录制的响应。打开旧会话后可以在入口框补上 # 后的页面路由。会话需要包含入口 HTML 和页面依赖的资源，缓存、正文截断、动态请求参数或手机端登录状态都可能影响复现效果。会话文件包含请求和响应正文，请按业务数据保存和分享。

复现默认从同源抓包自动读取 Cookie。手动输入优先，也可以关闭自动读取。历史抓包已从 Whistle 缓存移除时，可重新抓取或手动输入。Cookie 只注入本次隔离浏览器的入口域名，导出会话不包含此值。
