# UI 工作台升级方案

日期：2026-10-08。状态：代码布局审阅与概念方案，尚未修改生产 UI；尚未在真实 Whistle 容器中做视觉验收。

执行拆分见 [UI 3.0 改动点与待办](ui-3.0-todo.md)。全局导航确定为紧凑顶部导航，接口工作台左栏专用于模块/分组树。

## 现状与问题

- `AppLayout.js` 已渲染页面标题，模块、统计、嗅探、设置页面又渲染一次标题；信息层级重复。
- 应用内容区 24px padding 与页面容器 24px padding 叠加，再嵌套 Card；接口页还保留 220px 全局侧栏，数据可用空间偏小。
- 主题同时分布在 Ant Design token、布局内联配色、全局 CSS 与大量 `!important` 覆盖中；按钮硬编码绿/橙/青，主次不清晰。
- 接口页把模块选择、搜索、分组、批量操作、列设置铺在控制面板，主要任务仍依赖大表格和弹窗/抽屉。接口编辑存在两套长表单分支，统一修改成本高。
- 每个路由页面单独包裹 `AppLayout`，导航切换时应用壳状态容易重建；应将应用壳移至路由外，统一保存折叠和宽度偏好。
- 全局 CSS 使用通用类名、重复 reset 与组件覆盖，后续样式变化容易影响其他页面。

## 产品方向

以 API 开发工作台为默认体验。低饱和中性底色、一个主色、细分割线、紧凑而清晰的信息密度。品牌沿用 MockMaster，弱化渐变与发光装饰。状态使用文字、图标和颜色共同表达。

浅色/深色共享同一组件结构。现有赛博朋克/大地主题偏好保留迁移策略，先将组件接入统一 token，再决定是否作为可选配色继续保留。

## 应用壳

- 紧凑全局导航用于模块、接口、嗅探、统计、设置；品牌和版本放在导航区域。
- 顶部只保留一处当前模块/页面标题和当前页主要操作，避免占满一行的重复面包屑。
- 内容区直接承载工作台，避免白卡片套白卡片；同屏只使用一个强主按钮。
- 同步状态仅在已配置 WebDAV 时显示；不得把插件页面加载成功当作 Whistle 拦截已经生效。
- 场景切换属于后续能力，未实现前不得显示可用的虚假控制。

## 接口页：三栏工作台

左侧模块/分组树 → 中间接口列表 → 右侧当前接口详情。

- 左栏：模块开关、接口数量与分组；避免反复下拉切换模块。
- 中栏：名称、HTTP 方法、路径、启用状态、当前响应；筛选固定在列表上方。列设置等低频操作收进更多菜单。
- 右栏：规则、响应、调试三部分。响应内容是最大区域，状态码/延迟/Headers 为紧凑配置；先展示现有接口级设置，待 FEAT-03 后支持响应级覆盖。
- 切换响应立即区分“当前生效响应”与“正在编辑响应”；编辑草稿不要隐式改变运行配置。
- 编辑统一成一个组件，详情模式和抽屉模式复用；切换接口、模块或路由时提示未保存改动。
- 1024px 左右可收起模块树；768px 以下采用列表→详情的两级导航，保留返回列表入口。不强行压缩三栏。

## 其他页面

| 页面 | 升级方向 |
| --- | --- |
| 模块 | 保留卡片/列表切换，卡片只放名称、说明、接口数量和启用状态；导入导出收进次级菜单，分页放列表底部 |
| 嗅探 | 上方 URL/方法/发送；下方请求、响应左右分栏；历史抽屉保留完整响应，增加保存为接口/追加响应 |
| 统计 | 概览、趋势、热点接口、最近记录；支持时间范围和点击跳到接口，明确数据仅代表已记录请求 |
| 设置 | 按外观、匹配、录制、同步分组，统一说明和保存反馈；主题预览不影响已保存配置 |
| 诊断（待开发） | 同一引擎输出候选列表与判定步骤，和接口调试页复用展示组件 |

## 实施与验收

1. 提取 ThemeProvider、布局 token 与 PageHeader；将 AppLayout 移到路由外，清理冲突 CSS。先不改变后端 API。
2. 使用现有接口数据实现列表+详情，复用保存/开关/响应切换逻辑；保留批量管理入口。
3. 统一编辑器、请求测试和嗅探布局，再接入诊断与场景新能力。
4. 验证深浅主题、长 URL、中文长名称、大 JSON、空数据、请求失败、未保存切换与键盘操作。
5. 在 Whistle 插件真实容器内验证 360/768/1024/1440px；业务内容只有必要的代码编辑区域可水平滚动。

升级成效以同屏可见接口数量、编辑/切换响应所需步骤、误切换和丢失草稿情况评估；不以增加装饰或新增设置数量评估。
